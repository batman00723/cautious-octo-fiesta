================================================================================
FRONTEND HANDOFF & BACKEND ARCHITECTURE DOCUMENTATION
Project: ASData (Norwegian Companies Directory)
================================================================================

1. BACKEND TECH STACK & ARCHITECTURE
------------------------------------
- Framework: Django 6.0 + Django Ninja Extra
- Database: PostgreSQL 16
- Architecture: Fully Asynchronous API with strict type hinting (Pydantic schemas).
- Performance: 
  - PostgreSQL GIN (Generalized Inverted Index) enabled for lightning-fast Full-Text Search.
  - Rate Limiting enabled (30 requests/min for anonymous users) via LocMemCache to prevent scraping.
- Base API URL: http://127.0.0.1:8000/api/

2. DATA MODEL CONTEXT
---------------------
The database contains ~100,000 Norwegian companies, 250k roles/people, and full financial statements.
Key fields exposed to the frontend include:
- Organization Number (9-digit unique ID)
- Company Name
- City (business_city) & Postal Code
- Employee Count
- Industry (code & description)
- Organization Type
- Financials (Operating revenue)
- AI Summary (A programmatic zero-cost Norwegian summary injected with real DB metrics).

3. API ENDPOINTS DICTIONARY (For Next.js Frontend)
--------------------------------------------------

A. SEARCH
[GET] /api/search/?q={query}
- Description: Live search engine. 
- Input: `q` (string) - Can be a company name, keyword, or exactly 9 digits for an exact ID match.
- Output: Array of objects.
  Schema:
  [
    {
      "organization_number": "983975240",
      "name": "Firma AS",
      "business_city": "Oslo",
      "industry_description": "Programmeringstjenester"
    }
  ]

B. COMPANY PROFILES
[GET] /api/companies/{org_number}
- Description: Fetches the complete profile of a specific company.
- Output Schema:
  {
      "organization_number": "...",
      "name": "...",
      "organization_type": "...",
      "established_date": "YYYY-MM-DD",
      "employee_count": 0,
      "website": "www...",
      "business_address": ["Street 1"],
      "business_postal_code": "0101",
      "business_city": "Oslo",
      "business_country_code": "NO",
      "purpose": "...",
      "ai_summary": "Programmatically generated Norwegian paragraph describing the company."
  }

[GET] /api/companies/{org_number}/similar
- Description: Finds up to 5 similar competitors in the exact same city and primary industry.
- Output Schema: Array of objects (same structure as Search results, but includes employee_count).

C. CATEGORY HUBS (Browsing)
[GET] /api/hubs/municipalities/all
- Output: Array of all Norwegian municipalities `[{"municipality_code": "0301", "name": "Oslo"}, ...]`

[GET] /api/hubs/industries/all
- Output: Array of all industries `[{"code": "62.010", "description": "Programmering"}, ...]`

[GET] /api/hubs/municipality/{code}
- Output: Details of a specific municipality.

[GET] /api/hubs/industry/{code}
- Output: Details of a specific industry.

D. NEXT.JS STATIC SITE GENERATION (SSG)
[GET] /api/ssg/routes
- Description: CRITICAL FOR FRONTEND. This endpoint returns a massive flat array of string URLs representing every single page that needs to be statically built by Next.js `getStaticPaths` or `generateStaticParams`.
- Output Schema:
  [
    "/company/983975240",
    "/company/983975241",
    "/hub/municipality/0301",
    "/hub/industry/62.010"
  ]

E. FORMS
[POST] /api/forms/contact
- Input: JSON `{"name": "...", "email": "...", "phone_number": "...", "message": "..."}`
- Output: `{"success": true}`

[POST] /api/forms/deletion
- Input: JSON `{"organization_number": "...", "name": "...", "email": "...", "reason": "..."}`
- Output: `{"success": true}`

F. SEO SITEMAPS
- [GET] /api/sitemap/index.xml
- [GET] /api/sitemap/hubs.xml
- [GET] /api/sitemap/companies_{page}.xml

4. FRONTEND REQUIREMENTS & INSTRUCTIONS
---------------------------------------
1. Framework: Next.js (App Router or Pages Router).
2. Styling: Vanilla CSS with highly premium, modern aesthetics (glassmorphism, clean typography, dark/light modes, micro-animations). Avoid generic looks.
3. SSG Integration: Use the `/api/ssg/routes` endpoint at build time to statically pre-render all 100k company profiles for maximum SEO and loading speed.
4. Live Search: Implement a debounced search bar in the global navbar that hits `/api/search/?q=` and displays instant dropdown results.
5. Error Handling: The API will return standard HTTP errors (e.g., 404 if a company doesn't exist, 429 if rate-limited).
